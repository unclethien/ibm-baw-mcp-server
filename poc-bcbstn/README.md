# BCBSTN POC #1 — BAW UI Modernization Demo

**Objective**: Demonstrate IBM Bob accelerating modernization of legacy BAW Heritage Coach UIs into modern Carbon-based Client-Side Human Services.

---

## Files in this directory

| File | What it is |
|---|---|
| `ProviderEnrollment.twx` | Mock BAW 25 process app export (Provider Enrollment workflow) |
| `heritage-coach-before.html` | **BEFORE** — Heritage Coach rendered inside BAW 25 Process Portal |
| `carbon-cshs-after.html` | **AFTER** — Carbon Client-Side Human Service generated by Bob |

---

## Demo Script

### Setup (open both files side by side)

```bash
# Open both in your browser
open poc-bcbstn/heritage-coach-before.html
open poc-bcbstn/carbon-cshs-after.html
```

Or drag both HTML files into Chrome/Edge tabs.

---

### Step 1 — Show the problem (BEFORE)

Open `heritage-coach-before.html`. Walk through:

- **Table-based layout** — label/input pairs in rigid left-aligned rows
- **Section boxes** with gradient headers — hallmark of Heritage Coach rendering
- **No real-time validation** — errors only surface on Next click
- **Steps are disabled tabs** — can't navigate back without losing data
- **Zero responsive behavior** — fixed widths, unusable on mobile
- **Visual debt** — looks like a 2015 enterprise application

> *"This is what Blue Cross's Pharmacy Provider and Provider Enrollment workflows look like today, running inside BAW 25 Process Portal. The portal shell is modern, but the coach inside is still Heritage."*

---

### Step 2 — Show the TWX source

Open `ProviderEnrollment.twx` in a text editor. Point out:

- **Business objects** — `ProviderRecord`, `Address` — fully typed data model
- **Heritage Coaches** — 5 coaches with sections, controls, buttons
- **Services** — `LicenseValidationService`, `ProviderSystemIntegration` — REST integrations
- **Swim lanes** — Provider vs Enrollment Specialists

> *"Bob reads this TWX export, inventories every artifact, maps every variable and service call, and understands the complete application structure without us manually documenting anything."*

---

### Step 3 — Show the modernized output (AFTER)

Open `carbon-cshs-after.html`. Walk through:

| Feature | Heritage Coach | Carbon CSHS |
|---|---|---|
| Layout | Rigid label/input rows | Responsive Carbon grid |
| Navigation | Disabled tabs, no back | Interactive progress indicator, navigate freely |
| Validation | On-submit only | Real-time, inline, field-level |
| Accessibility | None | WCAG 2.1 AA (Carbon) |
| Mobile | Broken | Fully responsive |
| Design system | Custom/none | IBM Carbon (enterprise standard) |
| Components | Raw HTML inputs | Carbon TextInput, Select, RadioButton, Checkbox |

**Live demo interactions to show:**

1. Click **Next →** without filling NPI or Tax ID → Carbon inline error notification appears
2. Navigate **back and forward** between steps freely
3. **Save Draft** → visual feedback confirmation
4. Complete all steps → **Submit Enrollment** → success state

> *"Bob generates this as a fully functional Client-Side Human Service — HTML, CSS, and JavaScript — following IBM Carbon Design System and WCAG accessibility standards. It replaces the Heritage Coach directly in the BAW 25 task flow."*

---

### Step 4 — The factory story

> *"This is one workflow. Blue Cross has hundreds. Bob makes this repeatable:*
> *1. Export TWX from BAW*
> *2. Bob analyzes and documents the application automatically*
> *3. Bob generates the modernized Carbon UI*
> *4. Development team reviews and integrates*
>
> *What used to take weeks of manual recreation becomes a structured, accelerated process."*
